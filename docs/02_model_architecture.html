FastWAM 模型结构与训练/推理流程

本文档按当前仓库代码整理，主要覆盖 FastWAM、FastWAMJoint、FastWAMIDM 三个模型变体。具体尺度细节见 03_tensor_shapes.md。

1. 模型总览

视频路径 动作路径 条件输入 MoT 混合注意力 loss/output
当前配置中 video_dit_config.action_conditioned=false。也就是说 video expert 本身不把 action 拼进 cross-attention context；action 与 video 的交互主要发生在 MoT 的混合 self-attention mask 中。

2. 训练时的模型块

输入条件

video: [B,3,T,H,W]，范围 [-1,1]

action: [B,A,Da]，已归一化

context: [B,L,4096]，T5 cache

proprio: [B,A,Dp]，只取第 0 步作为额外 token

视频分支

VAE encode: [B,48,Tz,Hz,Wz]

Flow matching 加噪并固定第 1 个 latent frame

VideoDiT pre_dit: [B,Sv,3072]

动作分支

Flow matching 加噪: [B,A,Da]

ActionDiT action_encoder

ActionDiT pre_dit: [B,A,1024]

MoT 混合 Transformer

每层中 video/action token 先分别过各自 block 的 LayerNorm、time modulation、Q/K/V projection。

两路 Q/K/V 在序列维拼接，做一次带 mask 的 mixed self-attention，再按序列长度切回各 expert。

切回后每个 expert 继续做自己的 output projection、cross-attention 到 text/proprio context、MLP。

预测与损失

Video head 输出 [B,48,Tz,Hz,Wz]

Action head 输出 [B,A,Da]

loss = video flow target MSE + action flow target MSE

3. 推理时的模型块

接口 使用场景 主要流程 输出
model.infer_action LIBERO/RoboTwin benchmark 默认动作推理 输入单帧图像和 prompt/proprio，生成 action latent 并迭代去噪 {"action": [A,Da]}
model.infer_joint 需要同时观察未来视频 rollout 或 Joint/IDM 完整推理 初始化 video/action latent，按 scheduler step 迭代预测 flow target {"video": list[PIL], "action": [A,Da]}
model.infer 兼容统一入口 当前 FastWAM 中直接转调 infer_joint 同 infer_joint
训练时通常不加载 text encoder，而使用预计算 context；评测配置会设置 model.load_text_encoder=true，所以推理可以直接传 prompt。
